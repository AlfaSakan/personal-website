# Blog Page for CV Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Blog section to the `cv` React SPA (list + per-post detail pages, content from local Markdown files) and a companion Claude Code skill (`cv-blog-post`, living in `llm-wiki`) that drafts new posts from wiki content on request.

**Architecture:** `react-router-dom` (`HashRouter`) adds two routes on top of the existing tab-based `App`: `/` (unchanged tab shell, plus a new "Blog" tab listing posts) and `/blog/:slug` (a standalone detail page). Posts are Markdown files with YAML frontmatter under `src/content/blog/`, loaded client-side at build time via `import.meta.glob` and parsed with `gray-matter`; body renders via `react-markdown`. No server, no build-time content pipeline, no test framework (the project has none - verification is `npm run build`, `npm run lint`, and manual dev-server checks, matching existing project convention).

**Tech Stack:** React 19, TypeScript, Vite 6, Tailwind CSS v4, `react-router-dom`, `gray-matter`, `react-markdown`.

**Spec:** `docs/superpowers/specs/2026-09-02-blog-page-design.md`

## Global Constraints

- Router: `HashRouter`, not `BrowserRouter` (GitHub Pages project site has no SPA-fallback `404.html`).
- Post language: English (CV site's language), even though source wiki pages are in Bahasa Indonesia.
- Post content scope: only wiki `Concepts` category (technical/professional), never `Goals`/`Reflections`.
- Frontmatter `date` is always a quoted ISO string (`'YYYY-MM-DD'`), never an unquoted YAML date.
- No em dash (`-`) in any skill-generated writing.
- No new dependencies beyond `react-router-dom`, `gray-matter`, `react-markdown` (no typography/CSS plugin, no MDX, no test framework - reuse existing Tailwind tokens from `src/index.css` and the `cn()` helper).
- Visual language: reuse existing color tokens only (`bg-black`, `bg-eerie-black-1`, `bg-eerie-black-2`, `border-jet`, `text-orange-yellow-crayola`, `text-light-gray`, `text-light-gray-70`, `text-white-2`) - no new colors introduced.

- [ ] **Step 3: Create the loader utility**

Create `src/utils/blog.ts`:

```ts
import matter from "gray-matter";

export type BlogPostMeta = {
  slug: string;
  title: string;
  date: string;
  excerpt: string;
  tags: string[];
  sourceWikiPage: string;
};

export type BlogPost = BlogPostMeta & {
  content: string;
};

const rawPosts = import.meta.glob("/src/content/blog/*.md", {
  query: "?raw",
  import: "default",
  eager: true,
}) as Record<string, string>;

function parsePost(path: string, raw: string): BlogPost {
  const { data, content } = matter(raw);
  const slug = path.split("/").pop()!.replace(/\.md$/, "");

  return {
    slug,
    title: data.title,
    date: data.date,
    excerpt: data.excerpt,
    tags: data.tags ?? [],
    sourceWikiPage: data.sourceWikiPage,
    content,
  };
}

const allPosts: BlogPost[] = Object.entries(rawPosts)
  .map(([path, raw]) => parsePost(path, raw))
  .sort((a, b) => (a.date < b.date ? 1 : -1));

export function getAllPosts(): BlogPostMeta[] {
  return allPosts.map(
    ({ slug, title, date, excerpt, tags, sourceWikiPage }) => ({
      slug,
      title,
      date,
      excerpt,
      tags,
      sourceWikiPage,
    })
  );
}

export function getPostBySlug(slug: string): BlogPost | undefined {
  return allPosts.find((post) => post.slug === slug);
}
```

## Workflow

### 1. Pick a topic

If Ahmad names a topic or wiki page directly, use it. Otherwise:

1. Read `llm-wiki/index.md`, specifically the `## Concepts` section.
2. Propose 3-5 candidates suited to a recruiter/client audience - favor pages about AI/LLM engineering, backend/data systems, and professional practice (negotiation, freelancing) over pages that are purely personal-learning notes (e.g. spaced-repetition/memory-technique pages are learning-methodology, not portfolio material - skip those unless Ahmad specifically asks).
3. Never propose anything from `## Goals`, `## Reflections`, `## Health`, or `## Parenting` - those are out of scope for this skill regardless of how they're framed.

### 2. Read the source

Read the chosen wiki page in full (e.g. `llm-wiki/wiki/concepts/<Page Name>.md`). This is the factual grounding for the post - don't invent claims beyond what the page says.

### 3. Draft the post

Write in **English**, translated and rewritten for a professional audience, not a literal translation of the Indonesian wiki prose. Aim for the tone of `About.tsx`: concise, concrete, no hype. Structure:

1. A specific opening (what the concept is and why it matters in practice), not an abstract "Have you ever wondered..." hook.
2. One or more `##` sections breaking down the concept or its practical implications.
3. No sales pitch, no CTA - this is a technical portfolio piece, not a lead-gen post.

Target roughly 400-700 words.

### 4. Write the file

Frontmatter fields (all required):

```
---
title: 'Descriptive, specific title'
date: '2026-09-02'
excerpt: 'One sentence, under ~160 characters, for the list-view card.'
tags: ['tag-one', 'tag-two']
sourceWikiPage: 'Exact Wiki Page Name'
---
```

**Gotcha:** always quote the `date` value (`'YYYY-MM-DD'`) and the `title`/`excerpt` values if they contain a colon or start with a special character - unquoted YAML strings with `:` break frontmatter parsing.

File name: `<slug>.md` in `cv/cv/src/content/blog/`, where `<slug>` is a kebab-case version of the title.

### 5. Tone rules (non-negotiable)

- English, professional but not stiff - match `About.tsx`'s register.
- **Never use an em dash (-)** anywhere in the output. Use commas, periods, or plain conjunctions instead.
- No marketing/hype language, no rhetorical-question openers, no exclamation points.
- Every substantive claim must trace back to the source wiki page - if you want to add something the page doesn't cover, ask Ahmad first rather than inventing it.

- Which wiki page it's grounded in

Only write the file after Ahmad approves the draft.
